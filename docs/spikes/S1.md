## Measurements so far

Machine: the developer's Windows 11 Pro PC (not the reference machine). Node 26.12.0. Ten sequential spawns each, measuring from `spawn()` to the first stdout line (the `initialize` reply).

| Runtime artefact | Handshake (ms) | Bare `node -e 0` (ms) |
|---|---|---|
| Unbundled `tsc` output (`dist/main.js`, separate ESM modules incl. Zod) | 558–1193 | 216 |
| esbuild bundle (`dist/bundle/runtime.mjs`, 452 KB minified) | 178–312 | 107–141 |

Under a parallel Vitest run, the unbundled runtime took 2.2 s and broke NFR-002. Module loading costs most of the time on Windows (many small files, each scanned by antivirus), so:

- The sidecar must always run the bundle (ADR-0013 note).
- `RuntimeHarness` spawns the bundle, so tests measure what ships.
- Still to try: Node's module compile cache (`module.enableCompileCache()`) for a further gain. Try it once the Host exists.

## Behaviour verified by tests

`packages/runtime/src/runtime.test.ts` (in process) and `packages/runtime/test/stdio.test.ts` (real pipes) cover:

- The handshake, rejection of any call before `initialize`, a second `initialize`, and a major protocol mismatch (`runtime.protocol_mismatch`, `userAction: reinstall`).
- `runtime.shutdown` replies, then exits with code 0, and only after the reply has been flushed.
- EOF on stdin exits with code 0 (ADR-0002, detecting that the Host has died).
- Invalid JSON, a malformed envelope, an unknown method, invalid params and messages over 4 MiB all map to the JSON-RPC codes in ARCHITECTURE.md section 9.2.
